# 统一运行限制与 200 元项目预算

实现日期：2026-11-04。数据库迁移：`0007_runtime_budget`。这是第六周固定评测之前的运行控制工作，尚未实现评测集或 EvalRunner。

## 默认限制

| 项目 | 限制 |
|---|---|
| 项目预算 | 累计200元；140元提醒，180元停止新模型请求 |
| 每次请求输入 | 保守估算120,000 token，包含消息和工具定义 |
| 每次请求输出 | 最多20,000 token |
| 每个分析任务累计 | 600,000 token，包含输入、输出、格式修正和恢复调用 |
| 模型/工具调用 | 每任务最多6次模型请求、12次工具调用 |
| 时限 | 模型请求最多90秒，任务总时限600秒，恢复不重置 |
| 连续重复调用 | 同一工具及规范化参数，第3次尝试在执行前停止 |

记忆提取仍使用1,000输出 token，模型探针使用16或256输出 token。额度是上限，不保证生成长度；输出仍受剩余 token、金额和时限约束。客户端只能降低任务限额，服务端拒绝超出上限的配置。当前 `.env.example` 使用新默认值，本机 `.env` 的两个 token 配置也已同步更新。

新任务保存运行策略、报价及配置快照。旧任务保留原快照，恢复时采用原快照和当前服务端限制中更严格的值。

## 保守费用算法

初始已核查报价覆盖 `aliyun / deepseek-v4.1-flash / cn-beijing`，来源为[阿里云模型信息](https://help.aliyun.com/zh/model-studio/deepseek-v4-1-flash)，核查日期2026-11-04：忙时输入2元/百万 token，输出8元/百万 token；闲时和缓存存在折扣，但本地账本统一按忙时、输入未命中缓存的目录价计算，不抵扣优惠或免费额度。

```text
费用 = (输入 token × 2 + 输出 token × 8) / 1,000,000 元
120,000 输入 + 20,000 输出 = 0.40 元
```

金额使用 Decimal 和 PostgreSQL NUMERIC(18,8)，保留8位小数并向上取整。每次真实请求都保存独立 UUID、用途、关联运行、来源、报价版本、预估输入、输出上限、预留金额和实际 usage。修改报价不会改写旧请求的结算依据。没有已核查报价的模型或地域拒绝真实调用；DeepSeek 官方端点当前也需要先补充核查报价，不能自动套用阿里云价格。

预算从功能启用后累计，不追溯历史账单、不自动重置。200元是项目预算目标，180元为停止线，预留20元余量。台账不查询供应商余额、不覆盖本项目外调用，最终金额以阿里云账单为准。

## 预留与故障处理

每次发送请求前，网关在事务中锁定项目预算行，检查：

```text
已结算估算费用 + 所有尚未结算的预留金额 + 本次预留 <= 180 元
```

预留按本次输入估算和输出上限计算。首次达到140元时持久化提醒，并在分析时间线中记录预算事件。网关拿到 usage 后按实际 token 结算；即使报告 JSON 或引用校验失败，已发生的用量也计入费用。

| 请求状态 | 处理 |
|---|---|
| 已预留，确定尚未发送 | 取消时释放；过期且没有 dispatch 标记的预留可在后续请求时释放 |
| 已提交 dispatch 标记 | 供应商请求可能已发生，不因重启或租约过期释放 |
| 超时、中断、没有可靠 usage | 保留金额，标记或展示为未知用量 |
| 已有完整 usage | 幂等结算一次，释放对应预留 |
| 实际 usage 大于原预留 | 如实补记实际用量，停止不满足额度的后续请求 |
| 账本不可用 | 在真实请求发出前阻断；若结算阶段失败，原预留继续保留 |

已完成步骤的 checkpoint/journal 回放不会产生新的收费请求。真正重新发出的模型请求使用新的请求 UUID，旧中断请求的预留继续保留，不承诺模型调用 exactly-once。

所有真实入口复用 `DeepSeekModel` 的预算网关，包括分析、恢复、记忆提取、连通探针、工具调用探针和真实验收脚本。默认账本固定连接进程启动配置的主数据库，不随验收脚本临时分析数据库切换；跨库关联运行以 UUID 保存，不建立不存在的跨库外键。自动测试显式注入隔离账本，不访问用户真实额度。

## 循环停止与状态

工具指纹采用工具名和规范化 JSON 参数，统一字段排序、空白及 schema 默认值；非法参数同样保留稳定指纹。连续计数按实际请求顺序维护，不同工具、查询或分页会重新计数，同一批工具请求也逐条检查。

计数和已处理的逻辑调用标识保存在 `RunJournal`。第三次相同请求先持久化停止原因，再中止执行，不继续工具或模型调用；恢复重放已完成步骤不重复计数。停止后进入 `needs_attention`，用户手动重试会创建独立新 run。

新增错误码：`loop_detected`、`cost_budget_exceeded`、`pricing_not_configured`、`budget_unavailable`。后台任务保留原证据和调用 trace，预算受阻的记忆提取不生成候选。正常浏览、历史报告、假模型和健康检查不消耗额度。

## 只读接口与页面

- `GET /api/v1/budget`：项目阈值、已结算估算费用、预留、未知用量请求数、可继续预留金额及当前限制。
- `GET /api/v1/runs/{run_id}/cost`：该运行及关联记忆提取请求的费用记录；历史运行没有跟踪标记和费用记录时显示“未纳入账本”。
- 工作台公共区域显示可展开的预算摘要；成功和失败任务均可查看费用详情。分析时间线显示预算提醒、阻断和重复调用停止事件。
- 不提供预算修改、清零或重置接口。更新服务端配置后需要重启服务，账本金额继续保留。
