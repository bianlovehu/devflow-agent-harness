# 报告怎么写，结论怎么核对

第2版报告把内容分成三类：

- **事实**：已读材料直接表明的内容。例如“这个函数删除了按所有者筛选的代码”。
- **推测**：有线索，但还缺少条件或证据。例如“如果调用方传入其他用户的任务，可能返回这些任务；调用方尚未检查”。
- **建议**：后续可以做的事，例如补充测试、检查配置。建议不计为新增缺陷。

“事实”是报告的分类，不代表模型已经通过复核。页面分别展示“引用检查”和“结论是否被证据支持”。程序检查引用；结论是否成立由GPT对照原始材料另行复核。

## 每一项必须说清楚什么

| 页面内容 | 保存字段 | 要求 |
| --- | --- | --- |
| 事实、推测或建议 | nature | 分别为 fact、hypothesis、suggestion |
| 本次版本还是背景线索 | basis | current 或 reference；历史线索不能写成本次已确认问题 |
| 判断的对象 | claim_type | 代码行为必须直接引用本次代码；运行情况必须直接引用本次日志；历史线索不能替代 |
| 共同原因 | root_cause | 同一原因用相同名称，服务端据此合并 |
| 直接证据 | direct_evidence | 保存原文、原文位置和模型的观察；原文必须能在实际已读行中找到 |
| 成立前提 | prerequisites | 说明在什么条件下成立；没有额外前提可以为空 |
| 还没有确认 | unconfirmed_conditions | 推测至少写出一条缺口 |
| 严重程度依据 | severity_reason | 解释等级依据，不能把局部变化直接说成整个系统已受影响 |
| 不同后果 | consequences | 合并原因时保留不同后果和引用 |
| 影响范围 | reachability、call_chain | 只确认局部行为、范围未知，或提供本次代码调用链；没有调用链不能声称系统层面可触发 |

相同原因的多项内容合并后，保留原有证据、前提、缺口和不同后果。建议可以并入对应问题，也可以单独显示；单独建议的等级固定为“提示”。合并依赖模型明确填写的原因名称，不用关键词猜测两个问题一定相同。

## 哪些信息必须来自工具记录

`evidence_facts`由服务端生成，模型不能自行填入：

- **采集是否完整**：读取本次固定输入中的明确采集记录。缺少记录就显示未知。
- **原始材料是否被截断**：只接受采集适配器的明确标记。现有下载器没有给出该标记时，显示未知；日志短不等于截断。
- **保存材料是否读完**：根据工具实际返回的行号计算。少读、跳读和采集截断分开记录。
- **本次固定提交**：来自任务绑定的资源版本。默认仓库提交不能事后冒充本次CI提交；测试生成的快照也不能冒充远端Git提交。
- **是否启用知识库**：读取本次任务开关。没有启用不表示知识库为空，也不表示所有资料均无相关内容。

`boundary_claims`用于登记范围限制：声明原始材料被截断需要明确采集标记；声明还没读完需要实际存在未读行。工具的`next_line`只说明保存材料的续读位置。

代码审查和自动检查任务中，只有历史文档、旧记忆或旧提交，不能填写“本次版本已确认问题”。本次提交的代码、对应差异或对应运行日志必须提供依据。资料问答可以引用本次实际检索到的文档，但文档规定不能直接当作某次事件已经发生的记录。

## 引用检查和结论复核分开记录

- `citation_check=passed`：证据属于当前任务，行号有效、已经实际读取，直接引用的原文确实存在。
- `semantic_support.status=not_reviewed`：还没有检查“这段证据是否支持这个结论”。这也是新报告的默认值。
- 复核记录可以表达“证据支持、部分支持、证据不支持”，并写明复核者和理由。受测模型的输出不能把自己标成已通过复核。

程序不会自动证明任意自然语言推理正确。即使原文和行号都正确，仍可能算错、夸大影响、把相关性当成原因，或者提出错误建议。这些需要另行复核。当前已增加[限次复核与补查](report-review.md)：先核对证据记录，最多一次模型复核、一轮补查和一次修改。模型意见单独记录，不能把`semantic_support`改成自动通过。

## 旧报告怎么办

新报告带`report_version="2"`。旧报告保持原格式，仍可打开、引用和导出。旧任务恢复时沿用原来保存的格式，不能临时换成新格式。

旧报告没有记录分类、成立前提或严重程度依据时，页面显示“未知（旧版未记录）”。不重新猜测，也不补写成当时已经确认的事实。

## 怎样验证

`apps/api/tests/test_report_v2.py`覆盖四类历史错误：同一原因重复计数或把建议算缺陷；把短日志当截断、把知识库未启用当空库；没有调用链却断言整个系统受影响；把历史故障算成本次缺陷。同时验证引用有效不代表结论正确。

隔离数据库测试覆盖新版报告保存、读取、导出，以及旧任务与旧报告兼容。前端测试检查三类展示、原始发现下标和未知状态；统一检查命令仍为：

```powershell
.\scripts\check.ps1 -Integration -Build
```

该检查强制使用离线模拟模型，不消耗真实模型额度。本地运行步骤见[本地启动手册](local-runbook.md)。
