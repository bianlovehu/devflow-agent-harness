# 代码工作台：本地缓存与手动更新

代码页打开、刷新和切换页签只查询本地快照，不创建准备任务、不下载 GitHub 代码。首次尚无快照时显示手动拉取入口。

## 使用流程

1. 点击“拉取最新代码”：GitHub 仓库才检查远端默认分支并解析完整 SHA；人工样例使用本地固定提交。
2. 相同仓库、提交和策略的就绪快照直接复用，不重复下载。
3. 新提交进入现有 worker 的准备队列；发布成功后更新本仓库的代码浏览版本。
4. 后续普通访问读取已保存版本。刷新 GitHub 摘要、模型准备其他提交都不会替换手动选定的浏览版本。
5. 拉取失败仍保留上次成功的浏览版本；可返回缓存，也可手动重试当前固定提交。历史链接保持自身 SHA 和快照 ID。

浏览版本及请求目标存于仓库现有 `sync_state.code_workspace`，无新增迁移。GitHub 摘要同步在行锁内保留该状态；快照完成发布与浏览指针更新在同一事务进行。更新失败不修改已发布快照或旧任务的证据绑定。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET .../code/snapshots` | 本地默认浏览版本；无缓存返回 `snapshot=null`，不创建任务 |
| `GET .../code/snapshots?commit=<完整SHA>` | 只查询指定提交的已有快照 |
| `POST .../code/pull` | 用户显式检查远端默认分支并准备/复用快照 |
| `POST .../code/snapshots` | 保留固定提交准备与失败重试接口，供历史材料和任务使用 |

已存在的目录、文件、搜索和单快照状态接口保持兼容。PR/CI 分析仍按自身固定 base/head 或 CI head 按需准备材料；本次改变的是代码页面的自动准备行为。

## 归档换行差异

实查 `bianlovehu/recipegraph-rag` 的提交 `6304f8ba621412f886fb344f24eefa77fd902267`：Git 中 `README.md` 为 5351 字节、LF；下载归档为 5533 字节、182 处 CRLF。归档还原为 LF 后，大小及 Git blob SHA 完全匹配。

采集先验证归档原始字节；存在差异时，仅尝试 LF/CRLF 候选。候选必须同时匹配 Git tree 的字节数与完整 blob SHA，才按这些经过验证的原始 Git 字节保存。无法匹配仍报 `code_integrity_error` 并给出文件路径，不猜测混合换行，不容忍正文变更。归档扫描上限保持有效，单个归档条目最多允许原始文本上限的两倍以容纳 CRLF 扩展，最终 Git 文件仍不得超过 256 KiB。

覆盖信息中的 `newline_restored_files` 记录已恢复原始 Git 字节的文件数；制品 SHA-256、引用行号和 MCP/HTTP 校验沿用原流程。
