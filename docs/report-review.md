# 报告复核和补查怎么运行

本功能在原报告生成后运行。目的在于减少无依据的结论和建议，不给模型结果贴“认证正确”的标签。

本地更新源码后，按[本地启动手册](local-runbook.md)重启API和worker，再创建新任务即可使用。已有报告和旧任务保留原记录，不会因恢复运行而临时增加付费复核。

## 执行顺序

1. **先检查原文记录**：证据编号和内容是否匹配，版本是否仍属于本次任务，引用行是否真正读过，截断声明是否有采集标记，报告中的范围信息是否与工具记录一致。检查不通过就停止，不发起付费复核。
2. **最多复核一次**：出现高风险发现，或报告明确列出证据缺口、推测时，才触发复核。复核看到原报告、实际已读的原文和服务端记录；未读正文不会提前交给它。
3. **最多补查一轮**：复核认为缺少证据时，可以请求最多3次只读查询。只能访问本任务绑定的材料和当前仓库的知识库，沿用原有权限和预算。已经读过同一片段，不算获得新证据。
4. **最多修改一次**：根据复核意见和补查结果修改报告。这是内容修改，不是第二次复核；修改后的内容仍需要另行核对。

不增加原任务的总额度：全部阶段共用最多6次模型请求、12次工具请求、原有时间和输入长度限制，以及原200元共享费用账本和180元停止线。没有剩余次数、时间或费用时停止补查，不重置预算、不反复尝试。单次真实请求同时限制连接和完整响应的总等待时间；迟到响应不能再次记账。复核阶段预留结束报告的时间，剩余不足5秒就跳过。

旧任务的配置里没有启用该功能时，仍按旧流程执行，不在恢复时临时增加付费阶段。

## 复核只能给四种意见

| 意见 | 含义 |
| --- | --- |
| 可保留 | 说明哪些已读材料支持这段内容 |
| 需补证据 | 说明缺少什么，以及本任务允许范围内可以查什么 |
| 应降为推测 | 局部有依据，但成立条件、原因或影响尚未确认 |
| 应删除 | 没有依据、重复计算，或把建议、历史情况当成本次缺陷 |

每条意见必须指向原报告的具体发现或段落，附原文引用或明确的服务端记录依据。请求补查还必须说明目的。返回自信分、正确率或缺少依据的自评，不算有效复核。

复核会检查摘要、回答、失败步骤、验证建议、其他建议、未确认事项和范围说明，避免正文说“未知”，标题或建议却偷偷写成确定要求。发现发生修改时，摘要同步检查；降为推测不能代替修正错误算例。

## 失败如何分类

程序分别保存引用问题、版本问题、未读范围、元数据冲突、无依据截断、缺少上下文、原因推断不足、历史线索、同因重复、影响夸大、无依据建议和计算错误。分类是排查线索，不能代替对结论的核对。

- 原文检查失败：不发送复核请求，停止输出不一致报告。
- 复核返回无效内容或请求失败：不自动再复核，原有效报告保留，增加“复核未完成”的说明。
- 修改请求失败或没有预算：保守执行删除或降为推测，保留缺口；原报告和原意见仍可查到。
- 进程中断且不知道复核请求是否收到响应：不再次发送同阶段请求，避免恢复时偷偷增加复核次数。已保存完整响应的，直接恢复使用。

## 每次修改都重新绑定内容

`report_review`保存原报告、修改前后的内容编号、复核意见、费用所对应的调用记录和补查轨迹。编号由报告内容计算，内容改变后编号也会改变。

模型说“可保留”不会把`semantic_support`改成已通过复核。修改后的报告不能继承修改前报告的通过状态。页面明确提示模型意见仅供辅助；重要结论仍由GPT对照原文核查。

复核记录在报告接口、页面和Markdown导出中可见。旧报告没有记录时，显示没有自动复核记录。

## 怎样检查效果

真实对比使用现有20道开发题，保留同一次分析的原稿作为对照，记录复核后版本。资料查找使用隔离PostgreSQL/pgvector中的相同文档内容，避免更改日常知识库。原始资料、实际读取范围、前后报告、调用用量、费用和失败均保存；不会拿两次不同生成结果的差异冒充复核带来的改进。

GPT按预先保存的标准逐题核查，报告目标错误、误报、漏报、拒答、耗时与费用变化。出现原先通过、修改后失败的题目，必须解释具体退步。输出改变后，旧的GPT复核记录不能继续使用。

本轮20题的目标错误、拒答、耗时、费用和仍未解决的问题，见[复核前后对照](report-review-baseline.md)。本轮新增的评测结果、逐题复核、冻结和补查JSON只保留在本地，已加入Git忽略规则；固定题目和判断标准仍保留版本记录。

相关入口：

- `apps/api/src/devflow/report_review.py`：规则、一次复核、一轮补查及一次修改。
- `apps/api/src/devflow/review_eval_cli.py`：真实对比，分批运行并沿用共享账本。
- `scripts/report_review_comparison.py`：核对GPT记录与原输出是否对应，再汇总结果。
- `evals/report-review-criteria.json`：提前保存的判断标准与验收要求。
- `apps/api/tests/test_report_review.py`：预算、权限、次数、中断恢复和内容编号检查。
- `apps/api/tests/test_report_review_integration.py`：真实数据库保存与进程中断恢复检查。

本地完整工程检查仍用`.\scripts\check.ps1 -Integration -Build`。工程检查使用离线模拟模型，不代表真实模型质量，也不消耗真实模型额度。
