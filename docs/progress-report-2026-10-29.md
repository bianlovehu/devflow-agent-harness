## 本轮修复

| 问题与影响 | 修复与验证 |
| --- | --- |
| 模型返回非对象message时可能抛出AttributeError，被归为内部错误。 | 在模型入口校验响应、choice、message、tool_calls与function结构，统一返回model_format_error；4种异常message回归通过。 |
| 真实模型缺少usage字段时被默认为0；格式失败的已发生用量未计入修正预算。 | 真实请求要求完整usage；格式错误携带可校验用量，执行器记录并计入预算，超额时停止修正；缺失用量、格式修正及预算终止回归通过。 |
| 模型返回后恰好取消或超时，保存trace时再次触发停止检查，最后一次调用记录丢失。 | 保存诊断trace时仍校验状态与有效租约，允许记录已发生调用；继续禁止后续工具和成功报告提交。取消、超时与用量集成验证通过。 |
| 进入模型循环后重新计算总时长，单次模型超时没有扣除证据采集已用时间。 | worker把任务剩余时间传入执行器；每次模型请求按剩余总时长限制。集成用例将任务置于仅剩10秒，验证传给模型的timeout不超过10秒。 |
| 日志错误块只在最初4块内分页，后面的错误无法通过该模式继续读取；Unicode分隔符的行号口径与正文读取不同。 | 从当前原始行号继续搜索，保持每页大小限制；错误搜索和正文读取共用CR/LF行号口径。9个分散错误块可连续读完，原始行号回归通过。 |
| 仅获取目录、未读正文的空风险报告可能缺少明确的证据不足提示。 | 保留“证据不足时允许空风险”的既有设计；服务端在未确认事项中强制补充未读正文提示，避免误解为已充分审查。 |

实现集中于`agent.py`、`model_gateway.py`、`tool_gateway.py`和`worker.py`；新增15项测试，并加强原有取消测试。修正了worker文件用途说明中仍称“不调用模型”的过期描述。
