# 按问题检索长期记忆与效果对照

## 实现与默认策略

新增迁移 `0009_semantic_memory`，基于 `0008_checkpoint_tables`。升级后重启 API、worker 和前端：

```powershell
. .\scripts\env.ps1
uv run --locked python -m devflow.bootstrap
# 尚未准备本地模型时执行；请求期间不会自动联网下载
uv run --locked python scripts/prepare_rag.py
```

`MEMORY_RECALL_STRATEGY` 支持 `none`（无记忆）、`recent`（原有最近批准6条，默认）、`semantic`（按当前问题混合检索）。策略随新任务配置固定；旧任务无该字段时继续使用 recent。语义检索已经可用，但本轮实验没有证明答案质量收益，因此不切换默认值。页面的“按问题召回经验”始终使用 semantic，便于在改默认前检查真实结果。

semantic 先在数据库按人工批准、同仓库、未过期、指定完整提交或仓库通用过滤，再核对索引模型、内容版本和摘要/适用条件哈希。只有通过这些检查的经验才能进行向量与关键词评分，最终返回0至6条；不先截取最近6条，也不按全局top-k过滤。未提供当前提交时只检索仓库通用经验。无符合索引条件的条目时直接返回空，不加载模型。模型缺失/损坏时明确报错，不静默退回最近条目。

本地模型沿用固定 revision 的 multilingual-e5-small / CPU ONNX / int8 / 384维，带 query/passage 前缀。中文分词与代码标识符规则沿用知识库，记忆检索额外剔除单字及常见查询虚词。相关性门槛为语义余弦≥0.875或关键词覆盖≥0.25；得分为0.65×余弦＋0.35×关键词覆盖。门槛经过本开发集首轮校准，尚无独立留出验证。当前对过滤后的集合精确评分，不使用近似向量索引；大量经验时需评估性能。E5最长512 token，长文本尾部仍可通过全文关键词参与，但向量可能截断。

## 索引与冲突审核

每条记忆保存 content_revision、conditions、embedding_model、embedding_revision、embedding_sha256、indexed_at、index_status 和安全错误码。提取后为 pending，人工可以先编辑摘要、适用条件、版本和有效期；保存会增加内容版本、清除向量、取消原批准并清空旧冲突确认。先点击“重新索引”，索引就绪后再人工批准。失败可重试，原始异常不返回给浏览器。旧批准数据迁移后仍可用于 recent，但必须重新索引并审核后才能用于 semantic。

推理期间释放数据库事务；写回时获取仓库锁，强制刷新记录并比较内容版本与哈希，编辑/撤销竞态返回409，不能让迟到向量恢复旧内容。模型变化也不能复用旧向量。

所有新经验先进入候选审核。审核面板从整个同仓库有效批准集合寻找适用范围重叠的相关经验，展示旧摘要、适用条件、提交、来源报告和逐行diff。相似条目被视为“潜在冲突”，不能由模型自动判断真伪或覆盖。批准请求必须携带所审阅旧经验的ID与内容版本；并发编辑或新增相关经验会要求重新查看差异。确认后可并存，或明确替代一条同仓库批准经验。审核快照保存完整旧摘要、差异、来源、版本和审核时间。相似度检测不是完备的逻辑矛盾证明，仍需人工审核。

每次发出分析模型请求前重新召回并替换历史消息中的记忆；撤销、编辑、过期或版本失配不会继续注入旧消息。报告保存命中明细并展示来源、匹配原因和适用条件。历史运行明细是当时的记录，不会因事后撤销而改写原报告；撤销只约束后续请求。历史经验不成为当前代码证据，也不改变系统权限。

经验始终保留 source_run_id 和来源引用。单条可撤销；来源报告发现错误时，可点击“撤销该报告全部经验”，对应 `POST /runs/{id}/memories/revoke-source`，批量撤销该来源所有经验并保留原始记录。不会自动恢复被替代的旧条目。

## 三组真实对照结果（2026-11-13）

固定32条同仓库合成经验，其中6条较早的正确主题经验、24条背景经验、2条较新的故意误批准经验。8个当前问题，6题有相关经验，2题为自足计算/无关地层问题。每组同一 `aliyun / deepseek-v4.1-flash`、相同事实、相同预算（输入12,000、输出1,800、每次90秒），仅注入的历史经验不同。生产召回＋真实本地E5，24次真实回答均完成；标注不进入模型请求，负面记忆标识也不向模型暴露。合计输入20,672、输出2,904 token，按项目现有保守目录价估算0.064576元，最终以供应商账单为准。

| 策略 | 相关经验召回率（6题） | 平均记忆数 | 错误经验暴露题数 | 平均实际输入token | 自动断言质量 |
|---|---:|---:|---:|---:|---:|
| 无记忆 | 0% | 0 | 0/8 | 237.75 | 87.5% |
| 最近6条 | 0% | 6 | 8/8 | 1605.75 | 87.5% |
| 语义检索 | 83.3% | 2 | 1/8 | 740.50 | 87.5% |

语义检索命中了旧所有者隔离、游标分页、缓存事务、CI定位和迁移回滚经验，最近6条没有这些条目；真实输入比最近6条减少约53.9%，但仍比无记忆多502.75 token。标签题的正确经验漏召回，却命中了无关迁移经验；简单加法题因“函数”一词误召回错误空值经验。地层问题返回0条，其他题也没有为了数量填满6条。

当前代码已足以回答这些问题，因此三组自动断言质量相同，没有观察到答案收益。与项目历史约束相关、同义改写的问题具有召回收益；短泛问句、无关任务、自足代码题可能没有收益，甚至增加干扰和token。语义相似不保证经验正确：如果错误经验被人工误批准，仍可能被检索，不能取代审核、版本检查和当前证据核验。

自动质量每题按断言正确且引用有效当前事实ID的比例计分，不是完整语义质量。CI/地层题的“现有证据足以证明/可以确定”被所有策略判为 contradicted，解释均明确证据不足；标注用 needs_verification，存在措辞歧义，保持原始评分且不追改标注。对全部24条回答的Codex非盲解释复核未见跟随错误经验；这不等同于独立人工验收。最近组2题“暴露错误经验且自动评分未满”只是共现，不能归因于记忆干扰。真实生产干扰率仍未知。

本轮为开发集单次采样；首轮0.82门槛导致所有问题填满6条，被否决后收紧门槛并处理中文虚词。校准记录也保留。没有独立留出、重复采样或完整Agent工具链答案实验，不支持更改默认行为。进一步更改默认需要扩大真实任务集、冻结阈值后跑独立留出并做独立语义复核。

复现入口和固定输入见[固定数据集](../evals/memory-v1/README.md)。原始运行记录仅保留在本地 `evals/memory-v1/runs/20261113/`，不随 Git 提交：`report.md` 为逐题报告，`results.json` 为完整请求/回答/usage，`review.json` 为非盲解释复核，`calibration.json` 为首轮失败校准。其他机器可按复现命令生成自己的运行记录；本文保留本次汇总结果及局限。所有真实调用经过既有共享预算账本，不独立重置额度。
