# 第 4 步 前端主框架验收

日期：2026-10-28（Asia/Shanghai）

状态：第4步已完成。已连通仓库浏览、PR与CI任务创建、会话导航、任务详情和证据预览。任务执行器仍按后续步骤接入，当前任务状态为 queued。

## 已实现的流程

仓库列表 → 仓库详情 → 选择PR或CI → 新建或选择会话 → 提交问题 → 打开任务详情。

工作台地址为 `/runs`，任务直达地址为 `/runs/{runId}`。宽屏包含左侧会话与任务、中间问题与报告区域、右侧证据。1360px及以下用独立内容标签切换报告和证据；850px及以下将会话列表移到上方。代码和日志使用纯文本行号视图，并可展开完整原文。

任务详情来自持久化API，不生成假报告。页面显示任务UUID、任务类型、输入版本、问题、错误原因和已保存事件。任务间切换按仓库、会话、任务与制品ID隔离缓存；手动刷新重新读取当前记录。

## 类型与代理

新增 RuntimeInfo 和 ModelInfo 运行配置契约。使用锁定的 openapi-typescript 7.13.0，从本地 FastAPI 应用离线生成全部前端业务类型。类型生成不启动 lifespan、不连接数据库、不发模型请求。生成类型以CRLF保存，api:check在后端变更而未重新生成时失败。

业务代理按方法和路径限制范围，只开放资源与工作流的既有读取接口，以及创建会话和任务的POST。查询参数按接口允许 repo_id、limit、offset、after，重复、未知或格式不符时拒绝；制品读取必须指定仓库。写请求检查浏览器Origin、JSON格式、实际128KiB体积和幂等键格式。仅转发必要请求头，不复制Cookie或Authorization，不跟随上游重定向。

代理保留HTTP状态、错误码、request_id、X-Request-ID与Idempotency-Replayed，网络故障转换为带请求标识的503。仓库加载成功后才启动其资源查询，断连恢复时一次主查询重试可重新加载后续区域。

## 任务创建与重试

PR使用pr_review和PR编号，CI使用ci_debug和CI运行ID。创建任务时不额外调用消息创建接口，消息与初始事件由后端事务保存。

一次提交生成一个幂等键，重复点击复用进行中的请求；同一输入在结果未知后重试仍保留原键。后端201表示首次创建，200表示已有任务重放。409显示实际原因，需要核对或修改输入后再提交。会话创建不具备幂等键，结果未知时先核对会话列表，再选择已有会话继续任务提交。

数据库样例模式允许保存排队任务，task_execution_available=false不会被误解为禁止保存。文件模式显示限制说明并隐藏提交表单。表单失败后保留已填写问题及已知会话。
