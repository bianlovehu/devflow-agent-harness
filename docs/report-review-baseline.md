## 这次怎样比较

使用现有20道开发题，供应商为当前配置的阿里云，模型为`deepseek-v4.1-flash`。每题只生成一次初稿，保存该初稿，再执行最多一次模型复核和一次修改；比较的是同一初稿的前后版本。19份有效初稿都触发了复核；另1题原始分析格式失败，未进入复核。

资料检索使用隔离PostgreSQL/pgvector和已准备的本地E5权重，导入固定文档内容，不修改日常知识库。每批文档的实际版本编号、内容哈希和已读范围均保存。没有新增依赖，也没有在普通请求中下载权重。

判断规则在运行前已保存于[复核标准](../evals/report-review-criteria.json)，配置和源码编号见本轮冻结记录（本地文件`evals/freezes/report-review-v3-20261112.json`）。GPT逐题对照原始代码、日志、检索文档和实际已读范围，判断的是整份报告，包括摘要、后果及验证建议。模型给出的keep不能作为GPT判定通过的理由。

这些开发题已被查看，并用于改进提示词；本次不是盲测。模型生成和模型复核使用同一供应商模型，GPT担任用户指定的复核者，不宣称独立真人盲审。每题只有这一次配对样本，不能据此宣称稳定成功率或统计显著提升。

## 哪些改善，哪些仍有问题

- `ci-null`：保留测试失败和ValueError，删除“整个CI在单测阶段中断”等没有整体状态支持的断言。
- `ci-config`：保留DATABASE_URL异常，删除非零退出、后续步骤停下、合并发布被阻塞等没有证据的判断。
- `qa-missing`：从“全库没有SLA”改为“本次召回未发现SLA”；仍拒绝编造SLA数值。
- `pr-owner-fixed`发生退步：修改后的摘要新增“无源截断”，但工具只证明保存的两行已读完，原始来源是否截断仍未知。确定性检查核对结构化声明，没有理解这句自然语言；不能沿用初稿通过结论。

剩余7题：`pr-owner-removed`、`pr-null-labels`、`pr-owner-fixed`、`pr-page-boundary`、`pr-zero-divisor`、`ci-dependency`、`ci-oom`。问题包括夸大调用方或流水线影响、同因重复、未读requirements文件就确定直接版本约束，以及错误的切片泛化。降为推测、修改摘要或降低严重程度，都不能抵消正文仍有的错误。

分页题还暴露了参考文字不够准确：原标注“每页末尾遗漏一条”应限定满页。固定反例`items=[1,2,3], n=1, size=2`中，base的`[2:4]`和head的`[2:3]`都得到`[3]`。本次没有改原冻结输入或降低验收标准，GPT按实际语言语义核查；反例记录（本地文件`evals/regressions/report-review-page-counterexample-20261112.json`）保留该评分材料问题。自动契约检查不判断这条自然语言是否正确。
