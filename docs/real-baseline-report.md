# 真实模型测试结果与改进记录

更新日期：2026-11-11。已完成开发用题、压缩前后对比、同题重复测试，以及固定代码后新增题目的测试。GPT按用户要求，对照原始材料逐题检查结论。本文保留修改前后的结果和失败记录；完成测试不代表所有报告都正确。离线模拟模型（fake）只用于检查程序功能，真实模型的效果另行统计。GPT参与出题和复核，不属于独立人员的盲测。

## 名称和数字怎么看

- **关键词检索组**：按问题中的关键词查找资料。
- **混合检索组**：既找包含关键词的资料，也找意思相近的资料，再合并结果。
- **PR / CI / QA**：分别指代码改动审查、自动检查与测试、项目资料问答。
- **token**：模型计算输入、输出长度所用的单位，不等于汉字数；费用按它计算。
- **Recall@6**：前6条检索结果找到了多少相关资料。1.0表示全部找到，不表示回答全部正确。
- **严格通过 / 有备注 / 失败**：分别表示未发现实质问题、主要判断正确但仍需修改、存在漏报或错误结论或建议。“未生成可用报告”单独统计。

“每组20次”表示每种方法各执行了20次测试；成功生成多少份报告、多少份结论正确，在表中分别统计。

## 两种方案的对比，以及多次测试是否一致

测试直接使用应用实际的文档上传和检索功能：先用本地模型将文档转成向量，再通过Postgres/pgvector查找资料。在随机专用库导入5份开发集相关文档和8份固定背景文档；每批两组使用相同的文档内容和固定版本。测试结束后删除专用数据库，保留原文件和查询记录。

v2固定问题检索中，两组均在5个有相关资料的问题上Recall@6=1.0；另1个无相关资料的问题独立登记，不参与Recall均值。这组资料只有13份文档，两种方法都已找到全部相关资料，不能证明混合检索优于关键词，也不能推广到真实大型知识库。

历史压缩对照已有3题×2组的6次真实结果，历史稳定性已有3题×3次的9次结果，均在`data/baselines`保留。v3下的context-v2已执行6次：未压缩3/3产生有效报告，预算压缩仅1/3，另有一次budget_exceeded和一次内部IndexError。stability-v2已执行9次，8次有效，一次相同IndexError。不能把压缩token减少写成质量提高，也不能把有8份报告写成稳定成功。

压缩两组使用同样的12条历史对话、相同任务和证据；不压缩组的输入上限为120k token，压缩组为20k token（分别是12万和2万token）。20k必须容纳系统规则和必要约束，估算节省量与供应商实际输入token分别报告。代表题固定为pr-owner-removed、ci-lint、qa-owner。耗时包含模型、网络和工具，部分时段同时运行工程检查，不能作为严格的速度比较。

## 修复文档读取错误和压缩顺序问题

v3有三个任务在找到文档、再次读取时出现IndexError（读取超出范围）。原因是程序把文档末尾的换行多算了一行：实际只有1行，却记为2行；读取第2行时就异常退出。资料已经找到，错误出在文档读取功能。

修复后，登记行数和读取行数使用同一规则。对于旧文档多算的行数，读取时按实际内容处理，历史证据记录仍保留。请求不存在的第2行时，返回“行号超出范围”的错误，不再让程序崩溃。补充检查覆盖了三种换行格式（LF、CRLF、CR），也验证了通过真实数据库找到文档后可以再次读取。

之前的压缩顺序也有问题：先删掉刚读到的代码正文，最后才缩短旧对话。结果模型看不到刚读的内容，反复补读，最终超过输入长度限制。现在改为先缩短旧对话，再按需要压缩工具返回的内容，仍使用20k token的输入上限。用旧失败记录做了不调用真实模型的检查，确认第2、3次请求里仍保留代码正文；新增测试也检查工具请求和返回结果是否仍一一对应。

上述修正的58项针对性测试通过。修正后的固定计划在real-dev-v4-20261111（40次）、context-v3-20261111（6次）、stability-v3-20261111（9次）验证；三组均已执行完毕并完成逐题GPT复核，最终指标见下文。v2/v3原输出、错误、用量统计和费用完整保留。

```powershell
. .\scripts\env.ps1
uv run --locked python scripts/baseline_report.py --directory data/baselines/real-dev-v4-20261111 --review evals/reviews/gpt-real-dev-v4-20261111.json --output data/baselines/recomputed-dev.json

```

此工具仅汇总已保存结果，不调用模型；输出/输入校验值不匹配会拒绝复用复核。对结论是否正确的判断由GPT逐题写入review，不是汇总脚本根据参考标注自动生成。73个固定版本任务结果（开发40、压缩6、重复9、新题18）均有复核，含两条无最终报告的预算失败，不把它们计成语义漏报或免费调用。
